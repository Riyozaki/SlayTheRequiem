# Release notes — кандидат Б1–Б3, ещё не выпущен

**Unreleased.** Новый принятый DLL/PCK/архив пока не объявлен. Текущая строка manifest — `v0.0.1`, а не подтверждение
совместимости всех кандидатов с этим именем. Сборки различаются по source/input hash и трём artifact hashes.
Публикация/merge — отдельное решение владельца.

## Изменения в исходниках

- Надёжность выдач/сундука/оплаты/сохранений: устойчивые identities, pending/receipt/recovery, сохранение исходного save
  при отказе, защита от повторов и частичного результата. Не обещается универсальная atomic disk transaction.
- Отдельный мастер создания: origin/background → стартовый бонус **60 золота / обычное зелье / удаление 1 базовой** →
  сводка. Нео/Знамение отдельно. Full Path после 3-го босса при уровне ≥8; short Path после 1-го без этого порога.
- Реализация согласованного True/Лат/Раскола/caps, циклов боссов/контрмер и девяти направлений сборок.
  Перечень всех 21 боя/фаз/свиты сохранён; ни один не исключён из финальной приёмки.
- Шесть сохранённых иллюстраций карт, парные фазы Короля и формы Носителя Зверя, 20 различимых силуэтов карты/масок
  и 14 значков лагеря. Мастера, prompts, source-chain и детерминированные экспорты остаются в source archive.
- Локальный reduced motion, остановка добавочных loops/tweens при смене настройки/выходе из дерева, мгновенная
  фиксация фазового спрайта независимо от необязательной вспышки. Смерть/Revive отделены от idle/оружейной позы.
- Полка Кличей сохраняет клетки физических экземпляров и показывает ожидание подтверждённого возврата.
  Не трактует любое удаление записи как успешный возврат; не меняет боевые стопки.
- Чипы постоянных черт врага: event-invalidated collect/sort и redraw только по изменению/появлению/layout.
  Double-buffer builder переиспользует два списка вместо List/ToArray на каждую мутацию; исключение не публикует
  частичный список, rebind сбрасывает поколение. Повторное bind и абсолютное положение powers не должны накапливать
  узлы/сдвиг. Core/микрозамер этого helper не заменяют проверку реальных подписок в клиенте.
- Собственные звуковые players завершаются при звуке OFF; deferred player также теряет Autoplay до Ready.
  Одинаковые короткие AoE-hit bursts объединяются. Не обещается отмена уже играющего native/FMOD one-shot. Настоящий микс/multihit ещё не принят.
- G0 staging сохраняет внешний Compile-link Core-тестов; публичный кандидат содержит согласованные source/DLL/PCK,
  не private build directory. Финальная матрица/hash gate и `seal` не создают GitHub release автоматически.

## Что реально проверено, а что нет

На **`49288c96ed171c01b7197777ace9c2892392261c`** [CI 44275682452](https://github.com/Riyozaki/SlayTheRequiem/actions/runs/44275682452):
**877/877 Core** и пять успешных jobs, включая 24 release contracts. Локально — 33 проверки / 300 Python unit PASS;
C# grammar 319/0, Harmony declarations 137/0. Это не semantic mod build.

На том же 492 реально исполнены и strict-verified **28 C# cache trials** (5×24 powers, 12000 условных кадров,
7 повторений/workload). Внутри этого runner stress baseline → candidate: **5.975 → 1.384 ms**, **1480 → 2960 B**,
60000 → 12004 builds; idle **11.281 → .199 ms**, **1480 → 1480 B**. Дополнительные 1480 B — начальная ёмкость
второго буфера в измеренном workload, не новые List/ToArray на каждый rebuild и не нулевые allocations всей игры.

Предыдущий `6c1234d` (869/869) сохранён отдельно: старый List+ToArray builder выделял до **3 073 792 B** в stress.
Его regression стала основанием для исправления. Тайминги разных CI jobs не сравниваются как одна hardware session;
в обоих запусках baseline/candidate измерялись попарно. Это **не** Godot/FPS/доказательство улучшения native GC.
Точные SHA, raw trials, hashes/границы и source-only snapshot receipt — в [отчёте Б3](../review/stage-three-quality-implementation-2026-11-18.md).
Последующие source/pair changes требуют отдельного подтверждения, не наследуют эти PASS автоматически.

## Открытые выпускные ограничения

1. Новый полный build с легальными references, independent import/export/PCK-load и clean-install **здесь не исполнены**.
   Историческая успешная сборка/плейтест пользователя остаются действительными, но не проверяют новые правки.
2. Все prepared native adapters, реальные UI/ресурсы/настройки BaseLib, все 21 бой/формы/Пути, save/Continue/rollback и
   два клиента должны пройти финальную матрицу. Сейчас нет 12 принятых маршрутов или 5-актного кооп PASS.
3. Художественная приёмка — в игре: source previews и AI provenance не равны выбору/одобрению автора или лицензии.
   Часть старого собственного SVG-арта остаётся прежней; не объявлена автоматически соответствующей новому эталону.
4. Девять source recipes и синтетические экономические all-win ledgers не означают девять доказанно жизнеспособных
   билдов, native-калибровку, winrate или сбалансированность всех сложностей.
5. Кэш проверен в Core; реальное invalidation после gear/load, подписки/узлы за 100 оконных циклов и аппаратный
   baseline/result в игре ещё не измерены. UI 720p/1080p/1440p, scale, RU/EN, gamepad — открытая приёмка.
6. Совместимость с другими gameplay-модами и другими версиями игры/BaseLib не заявлена. Исходные жалобы `nope`/награды
   должны быть воспроизведены на реальном runtime-пути, а не закрыты предположением или числом автоматических тестов.

Ни синтаксическая проверка, ни каталог, ни этот список не снимают P0/P1. Любой поздний фикс повторно открывает
приёмку изменённого кандидата; старый PASS нельзя просто перенести на новую пару. См. COMPATIBILITY/FINAL_ACCEPTANCE.
