# Регрессионная приёмка — 18.11.2026

База сценариев: `8000886` · [аудит и N-01…18](main-audit-2026-11-18.md) ·
[план исполнения](../plan/stabilization-plan-2026-11-18.md).

**Ни один игровой пункт ниже не отмечен выполненным.** Это спецификация финальной проверки, а не отчёт о запуске игры.
По решению автора ручной, визуальный и двухклиентный плейтест — **только в самом конце**. Автоматические проверки идут сейчас.
N-01/CS1628 исправлен в исходнике; [реализация Б1 и границы проверки](stage-one-implementation-2026-11-18.md),
[evidence](evidence/stage-one-2026-11-18/README.md): **560/560 Core**, Python/content, 67 подготовленных (не исполненных) game adapters.
Для игровых пунктов нужен свежий полный build/PCK из легальной среды; tree-sitter/Core не заменяют его.

## 0. Правила проведения

Для каждого запуска записывать: commit DLL и PCK, версию игры/BaseLib, набор других модов, seed, профиль/конфиг,
героя/происхождение/предысторию, этаж/акт/сложность, режим solo/coop, ожидаемый и фактический результат, лог/скриншот.
Начать с чистого профиля/копии сейва без других gameplay-модов. Пользовательские сейвы перед миграцией копировать.

В таблицах `[ ]` означает **не выполнено**. После выполнения — `PASS/FAIL/BLOCKED`, дата и ссылка на артефакт;
не закрывать пункт просто потому, что изменён соответствующий код.

Подготовка сложных состояний — integration-fixture или отладочный сейв. Инъекции отказа/исключения обозначены явно;
это не требование сломать живое сохранение игрока.

### Инварианты для операций с данными

- Для переноса «колода ↔ сундук» суммарное число экземпляров не меняется; экземпляр ровно в одном месте.
- Сериализованные свойства карты/предмета сохранены, кроме явно разрешённых изменений.
- При отмене/отказе/ошибке до commit колода, сундук, деньги, материалы и флаги прогрессии остаются согласованы.
- Успех одного действия применён ровно один раз; повтор/старое сообщение не применяет его заново.
- Выдача обязательного предмета/карты и установка соответствующего флага не могут разойтись.

## 11. Критерий выпуска стабильной альфы

- Нет открытых P0, нет воспроизводимой потери карты/предмета/оплаты.
- Полная сборка и PCK проверены на выпускаемом commit, Core/Python/content остаются зелёными.
- Повторены исходные жалобы игрока N-07/N-15 и их исправления; отсутствие лога не записывается как PASS.
- Минимальная матрица игры: 3 героя × 4 пары дверей = **12 завершённых full-run маршрутов**, плюс short-run,
  минимум по одному проверенному переходу каждой формы/Пути и отдельная приёмка всех боссов. Это smoke, не баланс-выборка.
- Не меньше одного полного 2-клиентного 5-актного run, возврат Камня, загрузка и failure-сценарии; это не полная сертификация коопа.
- В каждой UI/арт-задаче отдельные отметки «файл/код готов» и «в игре принято».
- Известные ограничения и несовместимости опубликованы; для сохранений есть миграция или честное предупреждение до загрузки.
