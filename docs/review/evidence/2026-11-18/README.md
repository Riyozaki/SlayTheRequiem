## Файлы

- `checks.json` — 22 реально выполненные локальные команды, exit codes и краткие результаты. Команды приведены к
  `python3`; фактически использован отдельный Python venv с версиями зависимостей из JSON.
- `logs/` — stdout/stderr этих инструментов; абсолютный путь checkout нормализован в `$REPO`, результаты/предупреждения
  не изменены. `dotnet-install.log` — отдельно неудачная попытка установить SDK, **не** успешный запуск xUnit или сборки.
- `ci.json` — метаданные зелёного GitHub Actions run `44068073718` для того же commit. Три job, без full-mod build.
- `burden-model.txt` — вывод `python3 tools/sim/burden_sim.py --runs 10000 --seed 7`: 90 000 упрощённых траекторий.
  **Не боевой симулятор.** Допущения и проблемы точности разобраны в §6 основного аудита.
- [16 контактных листов](../../assets/2026-11-18/) — сохранены отдельно от исключённого `.arena`; это исходные
  картинки проекта в обзорной раскладке, а не скриншоты игры. Пояснения — [арт-ревью](../../art-audit-2026-11-18.md).

## Как воспроизводить

Из корня репозитория, Python 3.12+ и отдельное окружение:

```bash
python3 -m venv .venv
.venv/bin/pip install tree-sitter==0.26.1 tree-sitter-c-sharp==0.23.5 pillow==13.0.0 numpy==2.4.6
.venv/bin/python -m unittest discover -s tools/sim -v
.venv/bin/python tools/ci/check_csharp_syntax.py
.venv/bin/python tools/ci/check_loc.py
.venv/bin/python tools/assets/asset_manifest.py --check
.venv/bin/python tools/sim/burden_sim.py --runs 10000 --seed 7
```

Остальные команды и закреплённые источники — в `checks.json`. Для Harmony-check нужен checkout
`zhiyue/sts2-rl-agent@5d874e855ae1d0550d5c30416fadd7dbb0d133b7`, папка `decompiled`.
Сторонние исходники, игровые бинарники и установленное окружение в этот набор не включены.

Это **не** полный повтор всех шагов CI: например, отдельное клонирование sts2_database и генерация разметки ванильных
атак в этом локальном наборе не запускались. Успех CI указан отдельно и не подменён локальными результатами.

Для полного `dotnet build/test` требуются .NET 9 и разрешённые зависимости; для сборки мода дополнительно игровые DLL,
для PCK — соответствующий MegaDot/Godot. Их отсутствие здесь не отменяет историческую сборку пользователя `ec598de`.

Обновление результатов после исправлений должно записывать **новый commit и новый запуск**, не перетирать этим
PASS старого аудита. Все игровые сценарии отдельного чек-листа на 18.11 остаются открытыми.
