# Ограниченные проверки Б2, не симулятор прохождения

## Матрица направлений Б2.4

```sh
python3 tools/balance/build_directions.py --check
```

9 source-кандидатов, не 9 сыгранных жизнеспособных билдов. Матрица не доказывает итоговые вероятности наград.

## Б2.5: парный экономический журнал на настоящем C# Core

```sh
dotnet test mod/SlayTheRequiem.Tests
dotnet run --project tools/balance/Trace --configuration Release
```

Нужен SDK .NET 9; игра/BaseLib/MegaDot **не нужны этому отдельному проекту**. `Trace/BalanceTrace.csproj`
компилирует production `Core/**/*.cs`, не Python-копию формул и не stub игрового API.
Результаты по умолчанию в игнорируемой `.arena-ci/balance/`:

- `core-scenarios.json` — 60 журналов = **30 пар** (3 героя × 10 одинаковых seeds × revision 0/1), 300 строк актов;
- `core-scenarios.summary.json` — границы метрик/число сценариев/commit CI/SHA256 полного JSON;
- `core-scenarios.md` — условия и сравнение, включая обе кривые лавок и HP policy factors.

Можно указать `--json PATH --report PATH`. Десять меток seeds: `STRB2B0000`…`STRB2B0009`
(10 символов, верхний регистр, без I/O). Это ключи синтетической нагрузки, **не native генерация карт**.
Чётность/пары индекса покрывают четыре сочетания вариантов актов 2/4; реальная дверь и выбранный путь фиксируются отдельно.

**Что считается настоящим:** вычисление цен/Груза/очков/уровней/HP-множителей непосредственно production C# Core.
**Что задано искусственно:** распределение комнат, позднее положение лавок, все победы, желаемые карты,
корзина закупки, продажа старого оружия, распределение очков Груза и план лагеря. Посох/предмет нужной ступени не гарантирован
реальной витриной; трактат после изучения исчезает и не увеличивает вес.
Нет ходов, боя, AI, урона/лечения/смертей, реальных reward choices, дверей/путей карты, произвольных эффектов личности,
Нео/событий/сундуков, полного материального цикла ремесла или вероятности победы.

Остаток золота здесь **не** основание поднять цены или ослабить награды: модель не платит за реальное выживание.
Ограничение excess ≤ 5 — заданная стратегия отказа от sample-карт, а не измеренное поведение игроков.
`AuthoredBossHpMultiplier` — отдельный пример optional authored boss; не дополнительный бой/награда.
`PrimaryBossHpMultiplier` в этой reference-модели различает авторских боссов новых актов 2/4 и заимствованных 1/3/5.
Short/difficulty smoke-тесты изолированы от базовой серии, не объявляются калибровкой сложностей.

CI запускает runner после xUnit, сохраняет `core-economy-<sha>`. С `--annotate` он также пишет краткую сводку и
ограниченную gzip/base64url-копию этих же трёх **синтетических** файлов в check annotations: части по 1800 ASCII-символов,
не более 40, с общим SHA256. При сборке обязательны все части/проверка SHA; обрезанная строка не является evidence.
Один длинный notice оказался обрезан API и не использовался как полный output. Это транспорт реального C# output
на случай недоступности artifact storage, а не новая симуляция/нативное доказательство.

## Реальные игровые наблюдения — только на финальном плейтесте

В идентифицированной игровой сборке:

```text
str_trace on
str_passport
```

- `[RequiemBalance]` — `producer=native-game`, schema 1: run/seed/player/segment/timeline, правила и SHA артефактов,
  текущие золото/♥/Груз/ресурсы/уровни/колода/рука/экипировка/враги/отложенные карты.
- `[RequiemBalanceEnemy]` — состояние после EnemySetup: role, HP **до/после** команды scaling, факт запроса команды,
  вычисленный policy multiplier, act/config/revision. Множитель не выдаётся за применённый к объекту с выключенным scaling.
- `combat:start-hero-hook`/`room:hero-hook` — граница нашего HeroRecord, не всех native listeners;
  `combat:victory-pre-rewards` — **до получения наград**; `shop:enter-before-stock` — **до генерации витрины**.
- `camp:result`/`shop:result` сохраняют статус, включая отказ/partial; pending/mutating отражаются отдельно.
- Наблюдение не вызывает selector, game RNG, CanPlay, InventoryIdentity.Ensure, восстановление gate или регистрацию роли.
  Первое обращение к provenance читает/хеширует DLL/PCK/passport и кеширует ответ; логирование/сериализация имеют накладные
  расходы. Это не обещание отсутствия IO/allocations или нейтральности для performance-замеров.
- `str_trace off` выключает эти строки. Автоматической отправки нет. Логи содержат идентификаторы забега/игрока;
  перед публикацией проверить приватные строки соседних систем. Чужие saves/game DLL в evidence не класть.

После **реального** сбора, например:

```sh
python3 tools/balance/compare_traces.py .arena/final-playtest/host.log \
  --scenario .arena-ci/balance/core-scenarios.json \
  --out .arena/final-playtest/balance-observations.md
```

Утилита проверяет тип/producer/schema, противоречия чисел, порядок/конфликт дубликатов; не удваивает копии одного лога,
не склеивает segment/timeline разных попыток. Без native-строк возвращает ошибку, не подставляет Core-сценарий.
Совпадение seed/героя/revision — лишь ключ. Для side-by-side дополнительно требуются пять актов, Requiem 1,
Ascension 0 и однозначный сохранённый снимок `sys=1;five=1;short=0;hp=110`. При других/неизвестных настройках сравнение отключено.
Даже при совпадении меток не утверждает равенство native RNG/workload/личности и **не вычисляет delta**
между снимком до наград и synthetic post-boss balance. Отдельные enemy-строки надо сверять в исходном логе;
эта утилита не воспроизводит EnemySetup и не аттестует бинарники по полю producer.

Тесты `tools/ci/test_balance_traces.py` используют **выдуманные parser fixtures**, не игровые прогоны.
`check_economy.py` проверяет source wiring, не семантическую компиляцию мода.
Старая `tools/sim/burden_sim.py` остаётся отдельной трёхактной proxy-моделью: не заменяет этот runner и тем более бой.
Ручная/визуальная/двухклиентная приёмка, настоящие серии и сравнение с этим output — только в конце релизного цикла.
